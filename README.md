## 💡 الفكرة

بدل الدفتر الورقي أو ملفات الإكسل المتفرقة، **AH2** يعطي صاحب المحل أو النشاط التجاري لوحة واحدة يعرف منها في أي لحظة:

- **مين له فلوس ومين عليه فلوس** — إجمالي الأرصدة الموجبة والسالبة في الشاشة الرئيسية.
- **حساب كل عميل بالتفصيل** — كل إيداع وكل سحب بتاريخه ووقته ووصفه.
- **كشف حساب جاهز للإرسال** — نص، صورة، أو PDF يتبعت على واتساب أو أي تطبيق آخر.
- **نسخة احتياطية من بياناته** — داخل قاعدة البيانات أو كملف JSON على جهازه.

النموذج المحاسبي بسيط ومقصود: كل عميل له **حساب جاري** عند المحل (شبه المحفظة)، الرصيد = الإيداعات ناقص السحوبات. الرصيد الموجب يعني أن المحل مدين للعميل، والسالب يعني مبلغ مستحق للمحل عليه.

## ✨ أبرز المميزات

### 🔐 الحساب والمصادقة
- تسجيل حساب جديد ينشئ **مستخدم + مشروع (محل)** معًا، مع كلمة مرور مستقلة للمشروع.
- تسجيل الدخول برقم الهاتف أو البريد الإلكتروني، وجلسة صالحة لمدة **30 يومًا**.
- تطبيع أرقام الهواتف تلقائيًا (تحويل الأرقام العربية/الفارسية إلى إنجليزية، وتوحيد `+20` و`0020` إلى صيغة محلية).
- تغيير كلمة المرور وتحديث الملف الشخصي، وكلمة مرور إضافية لتأكيد العمليات الحسّاسة.

### 👥 العملاء
- إضافة/تعديل/حذف عميل (فرد أو شركة) مع العنوان والملاحظات.
- رقم هاتف العميل **فريد داخل المشروع** (منع التكرار).
- صفحة تفاصيل العميل: الرصيد، عدد الحركات، وكشف الحساب الكامل.
- بحث سريع في قائمة العملاء.

### 💰 الحركات المالية
- نوعان فقط: **إيداع/دفع (+)** و**سحب (−)** — مع المبلغ والتاريخ والوقت والوصف.
- **إلغاء حركة** (وليس حذفها) مع تسجيل `cancelled_by` و`cancelled_at` و`cancellation_reason`.
- شاشة "كل العمليات" وشاشة "عمليات العميل" مع فلترة وتفاصيل كاملة.

### 📤 المشاركة والتقارير
- توليد كشف حساب/فاتورة بثلاث صيغ: **نص منسّق**، **صورة PNG** (html2canvas)، **ملف PDF** (jsPDF).
- نطاقان للمحتوى: **الرصيد فقط** أو **كشف الحساب الكامل**.
- مشاركة مباشرة عبر: واتساب، تيليجرام، ماسنجر، IMO، Gmail، رسائل SMS، المزيد (Web Share API)، أو بلوتوث.
- تقارير وإحصائيات بفلترة بالتاريخ: إجمالي العملاء، الحركات، الإيداعات، السحوبات، صافي الموقف المالي + معاينة وطباعة.

### 🗂️ البيانات
- نسخ احتياطي داخلي (إنشاء / استرجاع) مع حجم الملف وتاريخه.
- تصدير/استيراد كامل بصيغة JSON مع عدّاد للعناصر المستوردة.
- إعادة تعيين البيانات (تصفير) بتأكيد.

### 🎨 تجربة الاستخدام
- تصميم عربي RTL بخطوط Cairo و IBM Plex Sans Arabic، ولوحة ألوان (كحلي + ذهبي + أخضر وظيفي).
- **ثيم فاتح / غامق / حسب النظام**، ويُحفظ لكل مستخدم على حدة.
- شعار مخصص للمحل يظهر في الفواتير والتقارير.
- إشعارات وعدّاد غير المقروء + سجل نشاط لكل عملية.
- تنبيه تلقائي عند **انقطاع الإنترنت**، وإشعارات نجاح/خطأ واضحة في كل خطوة.
- **شاشة مبدّل الشاشات (Screen Switcher)** للتنقّل السريع بين الـ35 شاشة أثناء التطوير والعرض.

## 🧮 منطق الرصيد

كل الحسابات تمر عبر دالة موحّدة واحدة: `src/utils/balanceUtils.ts`

```
الرصيد = مجموع الإيداعات النشطة − مجموع السحوبات النشطة
(الحركات الملغاة status = 'cancelled' تُستبعد تمامًا)
```

| حالة الرصيد | المعنى | العرض |
| --- | --- | --- |
| `> 0` | رصيد لصالح العميل — المحل مدين له | أخضر `رصيد لصالح العميل` |
| `< 0` | مبلغ مستحق للمحل على العميل | أحمر `مبلغ مستحق للمحل` |
| `= 0` | الحساب متعادل | محايد `الحساب متعادل` |

> المنطق مركزي في مكان واحد، وبالتالي تُعرض نفس النتيجة في الشاشة الرئيسية، تفاصيل العميل، الفواتير والتقارير — بدون أي تعارض.

## 🚀 التشغيل السريع

### المتطلبات
- **Node.js 22.5 أو أحدث** (يُفضّل **24 LTS**) — لأن المشروع يعتمد على وحدة `node:sqlite` المدمجة.
- أي من مديري الحزم: `npm` أو `bun`.

> ⚠️ على Node 22.x قد تحتاج تشغيل الخادم بعلامة `--experimental-sqlite`. على Node 24 يعمل مباشرة.

### الخطوات

```bash
# 1) استنساخ المشروع
git clone https://github.com/adelelaskry1987-design/Adel-elaskry.git
cd Adel-elaskry

# 2) تثبيت الاعتماديات
npm install        # أو: bun install

# 3) إعداد متغيرات البيئة
cp .env.example .env
#  ثم عدّل القيم داخله (انظر الجدول التالي)

# 4) تشغيل بيئة التطوير (الواجهة + الـ API على نفس المنفذ)
npm run dev        # أو: bun run dev
```

افتح المتصفح على: **http://localhost:3000**

قاعدة البيانات تُنشأ تلقائيًا في `data/ah2.db` عند أول تشغيل — لا تحتاج إلى أي إعداد يدوي أو سكربتات تهيئة.

### أوامر متاحة

| الأمر | الوظيفة |
| --- | --- |
| `npm run dev` | تشغيل الخادم + الواجهة (Vite في نمط middleware) |
| `npm run build` | بناء الواجهة إلى مجلد `dist` |
| `npm start` | تشغيل الخادم للإنتاج (يخدم `dist` + الـ API) |
| `npm run preview` | معاينة نسخة البناء |
| `npm run lint` | فحص الأنواع عبر `tsc --noEmit` |
| `npm run clean` | حذف `dist` |

## 🔧 متغيرات البيئة

انسخ `.env.example` إلى `.env`. **كل** قيمة سرية تُقرأ على الخادم فقط ولا تُرسل للمتصفح أبدًا.

### أساسي
| المتغير | الوصف | إلزامي |
| --- | --- | --- |
| `APP_URL` | الرابط العام للتطبيق، يُستخدم في بناء روابط استعادة كلمة المرور | نعم في الإنتاج |
| `GEMINI_API_KEY` | مفتاح Gemini (محفوظ للاستخدامات الذكية المستقبلية) | لا |

### إرسال البريد (لروابط استعادة كلمة المرور) — اختر مزوّدًا واحدًا
| المتغير | المزوّد |
| --- | --- |
| `RECOVERY_EMAIL_FROM` | عنوان المُرسِل (مشترك بين كل المزوّدين) |
| `RESEND_API_KEY` | Resend |
| `SENDGRID_API_KEY` | SendGrid |
| `BREVO_API_KEY` | Brevo / Sendinblue |
| `EMAIL_WEBHOOK_URL` + `EMAIL_WEBHOOK_SECRET` | Webhook/SMTP مخصص |

### إرسال الرسائل النصية (لأكواد OTP) — اختر مزوّدًا واحدًا
| المتغير | المزوّد |
| --- | --- |
| `TWILIO_ACCOUNT_SID` + `TWILIO_AUTH_TOKEN` + `TWILIO_FROM_NUMBER` | Twilio |
| `VONAGE_API_KEY` + `VONAGE_API_SECRET` + `VONAGE_FROM` | Vonage / Nexmo |
| `SMS_GATEWAY_URL` + `SMS_GATEWAY_API_KEY` + `SMS_SENDER_ID` | بوابة SMS محلية (VictoryLink / WhySMS / بوابة خاصة) |

> بدون هذه الإعدادات يعمل التطبيق طبيعيًا، وتُظهر شاشة الاستعادة أن قناة البريد/الرسائل غير مُهيّأة، مع توفير **طلب دعم يدوي** كبديل.

## 🗄 قاعدة البيانات

SQLite عبر `node:sqlite`، والمخطط يُنشأ تلقائيًا في `server/db.ts`:

| الجدول | الوظيفة |
| --- | --- |
| `users` | المستخدمون (هاتف فريد، بريد اختياري، كلمة مرور مُعمّاة) |
| `projects` | المشاريع/المحلات + كلمة مرور المشروع |
| `project_memberships` | ربط المستخدم بالمشروع + الدور + الصلاحيات (JSON) |
| `customers` | العملاء (فريد بالهاتف داخل المشروع) |
| `transactions` | الحركات المالية + حالة الإلغاء وبياناته |
| `notifications` | الإشعارات وعدّاد غير المقروء |
| `activity_logs` | سجل النشاط (من فعل ماذا ومتى) |
| `backups` | النسخ الاحتياطية (JSON مضغوط داخل القاعدة) |
| `auth_tokens` | توكنات الجلسات وتواريخ انتهائها |
| `account_recovery_tokens` | توكنات/أكواد الاستعادة مع عدد المحاولات والصلاحية |
| `recovery_rate_limits` | حدود المحاولات لمنع إساءة استخدام الاستعادة |
| `support_recovery_requests` | طلبات الاستعادة اليدوية عبر الدعم |

المخطط يتضمّن **ترقيات آمنة** (مثل إضافة عمود `phone_verified` إذا لم يكن موجودًا) وفهارس فريدة تُنشأ فقط بعد التأكد من عدم وجود تكرار — فلا تنكسر قاعدة بيانات قائمة.

## 🔌 مرجع واجهة الـ API

جميع المسارات تحت `/api`، وكل ما بعد `/api/auth/*` يتطلب ترويسة:

```
Authorization: Bearer <token>
```

### المصادقة والحساب
| الطريقة | المسار | الوصف |
| --- | --- | --- |
| `POST` | `/api/auth/register` | إنشاء مستخدم + مشروع + جلسة |
| `POST` | `/api/auth/login` | تسجيل الدخول (هاتف أو بريد) |
| `GET` | `/api/auth/me` | بيانات المستخدم والمشروع والصلاحيات |
| `POST` | `/api/auth/logout` | إنهاء الجلسة |
| `POST` | `/api/auth/change-password` | تغيير كلمة المرور |
| `POST` | `/api/auth/update-profile` | تحديث الاسم/البريد/الهاتف |
| `POST` | `/api/auth/set-project-password` | تعيين كلمة مرور المشروع |
| `POST` | `/api/auth/verify-project-password` | التحقق من كلمة مرور المشروع |
| `GET` | `/api/auth/recovery/status` | هل قنوات البريد/الرسائل مُهيّأة؟ |
| `POST` | `/api/auth/recovery/email/request` | إرسال رابط استعادة للبريد |
| `POST` | `/api/auth/recovery/email/verify-token` | التحقق من صلاحية الرابط |
| `POST` | `/api/auth/recovery/email/reset` | تعيين كلمة مرور جديدة |
| `POST` | `/api/auth/recovery/phone/request` | إرسال كود OTP |
| `POST` | `/api/auth/recovery/phone/verify-otp` | التحقق من الكود |
| `POST` | `/api/auth/recovery/phone/reset-password` | تعيين كلمة مرور جديدة |
| `POST` | `/api/auth/recovery/support-request` | طلب استعادة يدوي من الدعم |

### العملاء
| الطريقة | المسار | الوصف |
| --- | --- | --- |
| `GET` | `/api/customers` | قائمة العملاء مع الأرصدة |
| `POST` | `/api/customers` | إضافة عميل |
| `GET` | `/api/customers/:id` | تفاصيل عميل |
| `PUT` | `/api/customers/:id` | تعديل عميل |
| `DELETE` | `/api/customers/:id` | حذف عميل |

### الحركات والتقارير
| الطريقة | المسار | الوصف |
| --- | --- | --- |
| `GET` | `/api/transactions` | الحركات (مع فلترة) |

## 🔁 استعادة الحساب

نظام استعادة متكامل وثلاث قنوات:

1. **البريد الإلكتروني** — رابط يحتوي توكن مُعمّى، بصلاحية مؤقتة واستخدام لمرة واحدة.
2. **الهاتف (OTP)** — كود يُرسل عبر مزوّد SMS، مع عدّاد محاولات وحدّ أقصى.
3. **الدعم اليدوي** — نموذج يُسجّل الاسم والمشروع ووسيلة تواصل بديلة، وتُحفظ الطلبات للمراجعة.

كل المحاولات محكومة بجدول `recovery_rate_limits` (نافذة زمنية + قفل مؤقت) لمنع التخمين وإساءة الاستخدام، ولا تُخزَّن الأكواد/الروابط كنص صريح بل كـ hash.

---

## 🔒 الأمان

- كلمات المرور مُعمّاة بـ **scrypt** مع **salt** عشوائي لكل كلمة، ومقارنة بزمن ثابت (`timingSafeEqual`).
- توكنات الاستعادة تُخزَّن مُعمّاة، بصلاحية زمنية وحدّ محاولات.
- الجلسات بصلاحية 30 يومًا، وتُحذف عند انتهائها أو تسجيل الخروج.
- كل استعلامات قاعدة البيانات تستخدم **Prepared Statements** (حماية من SQL Injection).
- فصل البيانات بمستوى المشروع: كل استعلام مقيّد بـ `project_id` المستخرج من التوكن.
- أسرار المزوّدين (Resend/Twilio/…) تُقرأ على الخادم فقط ولا تظهر في الواجهة.

> ⚠️ قبل النشر الحقيقي: شغّل التطبيق خلف **HTTPS**، وأضف حدًا لمعدّل الطلبات على `/api/auth/*`، وراجع سياسة الاحتفاظ بالبيانات.
